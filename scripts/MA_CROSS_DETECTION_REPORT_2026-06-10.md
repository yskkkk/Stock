# YSTOCK 종목보관 — MA 탐색 조건 상세 보고서

**작성일:** 2026-06-10  
**대상:** 종목보관함 자동 탐색 (일봉·주봉)  
**관련 코드:** `server/golden-cross-detect.js`, `server/ma-align-detect.js`, `scripts/pine-daily-weekly-ma-cross.pine`

---

## 1. 개요

종목보관 탭의 **자동 탐색**은 크게 두 가지 독립 조건으로 종목을 찾습니다.

| 구분 | 저장 source | 한 줄 요약 |
|------|-------------|------------|
| **MA 교차** | `golden_cross` | 특정 봉에서 이동평균선이 **교차한 순간** 탐지 |
| **정배열** | `ma_align` | 마지막 봉 시점에 MA5>20>60>120 **상태**가 성립 |

각 조건은 **일봉(1d)** 과 **주봉(1wk)** 에 대해 **별도 스캔**되며, 동일 종목이 양쪽에서 모두 잡히면 **일봉·주봉 교집합**으로도 리포트됩니다.

**탐색 유니버스**

- 국내: 시총 상위 약 300종목 (`loadBoxRangeCatalogUniverse` → kr)
- 미국: S&P 500 구성종목 (us)

## 2. 공통 기술 정의

### 2.1 이동평균 (SMA)

- **계산:** 종가(`close`) 단순이동평균
- **공식:** 최근 N봉 종가의 산술평균 (Pine `ta.sma(close, N)` 과 동일)
- **구현:** `server/golden-cross-detect.js` → `sma(closes, period)`

### 2.2 골든크로스 (상향 돌파)

Pine `ta.crossover(fast, slow)` 와 동일:

```
전봉: fast ≤ slow
현봉: fast > slow
```

코드: `isGoldenCrossBar(fastPrev, fastNow, slowPrev, slowNow)`

### 2.3 데드크로스 (하향 이탈)

Pine `ta.crossunder(fast, slow)` 와 동일:

```
전봉: fast ≥ slow
현봉: fast < slow
```

코드: `isDeadCrossBar(...)`

### 2.4 판정 봉 (중요)

- 스캔은 **해당 타임프레임 캔들의 마지막 봉**을 기준으로 합니다.
- **전봉 vs 현봉** 한 쌍만 비교합니다. (과거 봉에서 이미 교차했으면 마지막 봉에서 다시 교차하지 않는 한 **재탐지되지 않음**)
- 교차가 발생한 봉의 날짜는 `crossDate` (KST `YYYY-MM-DD`)로 저장됩니다.

### 2.5 최소 데이터

| 조건 | 최소 봉 수 | 이유 |
|------|-----------|------|
| MA 교차 | **121봉** | MA120 계산 + 교차 비교에 전봉 필요 |
| 정배열 | **120봉** | MA120 값 필요 |

## 3. 조건 A — MA 교차 (`golden_cross`)

### 3.1 탐지되는 6가지 교차 종류

한 종목·한 타임프레임·**마지막 봉**에서 아래가 **동시에 여러 개** 잡힐 수 있습니다.

| 코드 | 표시명 | 빠른 선 | 느린 선 | 골든/데드 | Pine 지표 |
|------|--------|---------|---------|-----------|-----------|
| `5>20` | 5→20 골든 | MA5 | MA20 | 골든 | ✅ 동일 |
| `5<20` | 5→20 데드 | MA5 | MA20 | 데드 | ✅ 동일 |
| `5>60` | 5→60 골든 | MA5 | MA60 | 골든 | ❌ Pine 미표시 |
| `5>120` | 5→120 골든 | MA5 | MA120 | 골든 | ❌ Pine 미표시 |
| `20>120` | 20→120 골든 | MA20 | MA120 | 골든 | ✅ 동일 |
| `20<120` | 20→120 데드 | MA20 | MA120 | 데드 | ✅ 동일 |

**수식 예시 (`5>20` 골든)**

- `MA5[전봉] ≤ MA20[전봉]` 이고 `MA5[현봉] > MA20[현봉]`

**수식 예시 (`5<20` 데드)**

- `MA5[전봉] ≥ MA20[전봉]` 이고 `MA5[현봉] < MA20[현봉]`

**참고:** `5>60`, `5>120` 은 **골든만** 탐지합니다 (데드 `5<60`, `5<120` 은 없음).

### 3.2 탐지되지 않는 것

- MA60 ↔ MA120 교차
- MA5 ↔ MA60 데드크로스
- 정배열 상태만 있고 **교차가 마지막 봉에 없는** 경우
- 마지막 봉이 아닌 과거 봉에서만 발생한 교차

### 3.3 일봉 / 주봉 적용

| 타임프레임 | 차트 데이터 | 의미 |
|-----------|------------|------|
| `1d` (일봉) | 일봉 캔들 | **일봉** MA5·20·60·120 기준 교차 |
| `1wk` (주봉) | 주봉 캔들 | **주봉** MA5·20·60·120 기준 교차 |

동일 함수 `detectMaCrosses()` 를 각 TF 캔들에 적용합니다.

### 3.4 스캔 제외 (tradable 필터)

아래에 해당하면 **교차가 있어도 스킵**됩니다 (`golden-cross-tradable.js`).

| 사유 | 조건 |
|------|------|
| `insufficient_candles` | 유효 캔들 < 121 |
| `invalid_closes` | 유효 종가 개수 < 121 |
| `no_quote` | 현재가·통화 없음 |
| `stale_last_bar` | 마지막 봉이 너무 오래됨 (일봉 기본 21일, 주봉 기본 28일 이내) |
| `kr_naver_unavailable` | 국내 + 네이버 시세 연동 시 네이버 가격 없음 |

## 4. 조건 B — 정배열 (`ma_align`)

### 4.1 탐지 조건

**마지막 봉** 시점에 아래가 **모두** 참이면 탐지됩니다.

```
MA5 > MA20 > MA60 > MA120
```

- 교차 순간이 아니라 **현재 배열 상태**
- 골든/데드 구분 없음
- 표기: `5>20>60>120`

### 4.2 일봉 / 주봉

MA 교차와 동일하게 일봉·주봉 각각 스캔합니다.

### 4.3 스캔 제외

MA 교차와 **동일한 tradable 필터**를 사용합니다 (`isGoldenCrossTradable`).

## 5. 일봉·주봉 교집합

스캔 완료 후 (`vault-scan-intersection.js`):

| 교집합 종류 | 조건 |
|------------|------|
| 골든크로스 교집합 | 동일 symbol이 **일봉 MA 교차** + **주봉 MA 교차** 목록에 모두 존재 |
| 정배열 교집합 | 동일 symbol이 **일봉 정배열** + **주봉 정배열** 목록에 모두 존재 |

교차 **종류**가 일치할 필요는 없습니다 (예: 일봉 `5>20`, 주봉 `5>60` 이어도 교집합 가능).

## 6. TradingView Pine 지표와의 관계

**파일:** `scripts/pine-daily-weekly-ma-cross.pine`

| 항목 | Pine | 서버 스캔 |
|------|------|-----------|
| MA 기간 (선) | 5, 20, 60, 120 | 동일 (교차 계산에 5·20·60·120 사용) |
| 일봉 MA | `request.security(..., "D", ...)` | 일봉 캔들 SMA |
| 주봉 MA | `request.security(..., "W", ...)` | 주봉 캔들 SMA |
| 교차 쌍 | 5↔20, 20↔120 (골든·데드) | 위 4종 + **추가** 5→60·120 골든 |
| 교차 마커 위치 | 5-20 → MA5, 20-120 → MA20 | (차트 표시 전용) |
| 탐지 시점 | 차트에 보이는 각 봉 | **마지막 봉 1개**만 스캔 |

**차이 요약**

1. 서버는 Pine보다 **`5>60`, `5>120` 골든** 2종을 **추가** 탐지합니다.
2. 서버 스캔은 **종목보관 배치** 기준이라 **최신 봉 1개**만 봅니다. Pine은 과거 모든 봉에 마커를 표시합니다.
3. 분봉 차트에서 Pine은 일·주봉 MA가 `request.security` 로 계단형 갱신됩니다. 서버는 해당 TF 캔들만 사용합니다.

## 8. 전체 요약 표

### MA 교차 — “이 종목이 잡히는가?”

```
[마지막 봉에서]
  (MA5 전봉 ≤ MA20 전봉 AND MA5 현봉 > MA20 현봉)  → 5>20
  (MA5 전봉 ≥ MA20 전봉 AND MA5 현봉 < MA20 현봉)  → 5<20
  (MA5 전봉 ≤ MA60 전봉 AND MA5 현봉 > MA60 현봉)  → 5>60
  (MA5 전봉 ≤ MA120 전봉 AND MA5 현봉 > MA120 현봉) → 5>120
  (MA20 전봉 ≤ MA120 전봉 AND MA20 현봉 > MA120 현봉) → 20>120
  (MA20 전봉 ≥ MA120 전봉 AND MA20 현봉 < MA120 현봉) → 20<120

AND 유효 캔들 ≥ 121
AND tradable 필터 통과
→ golden_cross 로 종목보관에 추가
```

### 정배열 — “이 종목이 잡히는가?”

```
[마지막 봉에서]
  MA5 > MA20 > MA60 > MA120

AND 유효 캔들 ≥ 120
AND tradable 필터 통과
→ ma_align 로 종목보관에 추가
```
